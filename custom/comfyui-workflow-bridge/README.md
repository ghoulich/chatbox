# Chatbox ComfyUI Workflow Bridge

This extension synchronizes paired ComfyUI UI-format and API-format workflows
with Chatbox. It is intentionally not a custom generation node and has no model
or Python package dependencies.

## Compatibility and API

The bridge targets ComfyUI `v0.34.5` and uses that release's
`PromptServer.instance.user_manager` to resolve the current user's isolated data
directory. It does not require the public `/userdata` endpoints.

The reverse proxy only needs to expose these authenticated routes:

- `GET /chatbox-bridge/v1/health`
- `GET /chatbox-bridge/v1/workflows`
- `GET /chatbox-bridge/v1/workflows/{id}`
- `POST /chatbox-bridge/v1/workflows`
- `DELETE /chatbox-bridge/v1/workflows/{id}?expectedRevision=N`

Requests continue to use the same Basic Auth protection as the ComfyUI site.
Do not exempt the bridge prefix from authentication.

Each managed workflow is stored twice inside the current ComfyUI user's data
directory:

- `workflows/Chatbox/<name>--<id-prefix>.json`: UI-format, visible to ComfyUI.
- `chatbox-bridge/workflows/<id>.json`: paired UI/API data and synchronization metadata.

Updates and deletes require the current revision. Stale writes receive HTTP
409 instead of silently overwriting remote changes. File names and paths are
generated by the bridge, JSON bodies are limited to 10 MiB, and writes use an
atomic temporary-file replacement.

## Build and local verification

The extension is pure Python and JavaScript, so there is no binary build step.
From the Chatbox repository root, verify it with:

```bash
python3 -m compileall -q custom/comfyui-workflow-bridge
PYTHONPATH=custom/comfyui-workflow-bridge \
  python3 -m unittest discover -s custom/comfyui-workflow-bridge/tests -v
```

## Install with an existing custom_nodes host mount

Copy the directory into the host path mounted as ComfyUI `custom_nodes`:

```bash
cp -a custom/comfyui-workflow-bridge \
  /HOST/COMFYUI/custom_nodes/chatbox_workflow_bridge
```

The destination must contain `__init__.py`, `routes.py`, `bridge_store.py`, and
the `web/` directory directly. Restart the workload after copying:

```bash
kubectl rollout restart deployment/<COMFYUI_DEPLOYMENT> -n leapchat
kubectl rollout status deployment/<COMFYUI_DEPLOYMENT> -n leapchat
```

For a StatefulSet, replace `deployment` with `statefulset`.

## Install by building a container image

When `custom_nodes` is baked into the image, add this after the ComfyUI source
has been copied:

```dockerfile
COPY custom/comfyui-workflow-bridge \
  /opt/ComfyUI/custom_nodes/chatbox_workflow_bridge
```

Adjust `/opt/ComfyUI` to the image's real ComfyUI root, build and publish the
image normally, then update the workload image. No `pip install` is required.

## Ingress example

If the current Ingress only forwards an allow-list of ComfyUI API paths, add
`/chatbox-bridge` to the same authenticated backend. Do not rewrite or strip
the prefix. A generic Kubernetes path entry is:

```yaml
- path: /chatbox-bridge
  pathType: Prefix
  backend:
    service:
      name: <COMFYUI_SERVICE>
      port:
        number: 8188
```

The existing `/prompt`, `/history`, `/view`, `/models`, `/object_info`, and
`/upload/image` routes remain necessary for generation features.

## Use in ComfyUI

After restart, open ComfyUI and choose **Chatbox Bridge → Sync current workflow
to ChatBox**. The command calls ComfyUI's own `graphToPrompt()` conversion and
sends both the editable graph and executable prompt to the bridge. Normal
ComfyUI saves that have not used this command are listed as unmanaged and need
to be opened and synchronized before Chatbox can execute them reliably.

## Use in Chatbox

1. Open **Settings → ComfyUI Image Generation → Connection**, enter the same
   endpoint and Basic Auth credentials used for ComfyUI, and run both connection
   checks.
2. Open **Workflow Designer** to create a text-to-image, image-to-image, optional
   LoRA, or ControlNet workflow. Chatbox generates both the editable UI graph and
   executable API graph.
3. Open **Workflow Library** to choose the active workflow, synchronize local
   changes, pull a remote revision, or delete a managed workflow from one or both
   sides.

Image-to-image and ControlNet profiles require exactly one reference image at
generation time. If another client updates the same managed workflow first,
Chatbox reports a revision conflict and requires a refresh/pull before another
push. Workflows listed as unmanaged are never overwritten or deleted by Chatbox.

## Upgrade and uninstall

Replace the extension directory and restart the workload to upgrade. Do not
delete the ComfyUI user data volume during upgrades.

To uninstall, remove `custom_nodes/chatbox_workflow_bridge` and restart. Managed
UI workflows remain under `workflows/Chatbox`; paired metadata remains under
`chatbox-bridge/workflows`. Remove those user-data directories separately only
after exporting any workflows that must be retained.
