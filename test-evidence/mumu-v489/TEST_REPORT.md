## 2. 本轮功能改动

- 新增“设置 → 默认模型 → 会话附件处理方式”：`自动（推荐）`、`内联全文`、`嵌入检索`。14 个 locale 均含对应文本。
- Android 增加会话附件向量索引、查询和清理。嵌入检索使用用户设置的嵌入模型；若已配置重排序模型，向量召回后继续重排。
- 修复移动端自定义 OpenAI 嵌入请求误走 WebView 全局 `fetch`：现在与普通模型请求一致，经原生 HTTP/代理链路发送。
- 修复重排序供应方 Base URL 未自动补 `/v1` 的问题。
- 修复选择搭档后会话标题一直停留在搭档名称的问题。搭档名称现在只是自动标题的占位标题；用户手动改名仍受异步覆盖保护。
- 修复 SearXNG URL 为空或非法时，在缓存键构造阶段直接抛浏览器原生 URL 异常的问题；现在统一显示可理解的 Chatbox 配置错误。
- 修复受影响的测试夹具，使 Web 搜索和附件所有权测试与 v1.23.1 当前接口一致。

## 4. MuMu 端到端验证

### 4.1 安装、启动与数据保留

- 冷启动成功，进程正常；用户原有会话、模型、SearXNG、Skills 目录和设置均保留。
- MuMu 全局代理仍为 `192.168.1.102:18888`，没有遗留 `adb reverse`。

### 4.2 附件：内联全文与嵌入检索

使用 6,457 bytes、72 行的受控 Markdown 文档，包含六组分散事实。

- 内联全文：回答 6/6 项正确，约 8.8 秒；没有调用嵌入或重排序模型。
- 嵌入检索：`qwen3-embedding` 建立 7 个 chunks、1024 维索引，索引耗时约 3.6 秒；查询时向量召回 7 项，并由 `qwen3-reranker` 成功重排 7 项。核心问题答案正确。回答中的一个说明性年份被生成模型误写为 2022，而原文是 2032；索引和召回日志包含正确原文，因此判定为最终生成阶段的事实转写错误，不是检索缺失。
- 设置页面最终恢复为“自动（推荐）”，嵌入模型 `qwen3-embedding`、重排序模型 `qwen3-reranker` 保持不变。

选择建议：小文档、需要完整总结或精确核对全文中分散事实时优先“内联全文”；长文档、多附件或围绕同一材料反复问局部问题时优先“嵌入检索”。内联更直接且没有额外索引调用，但占用上下文；检索节省上下文，代价是首次索引时间、嵌入/重排调用，以及召回范围可能遗漏全局信息。Android 的“自动”当前沿用平台默认，即使用内联全文；需要实际使用已配置的嵌入/重排模型时应手动选择“嵌入检索”。

### 4.3 搭档标题、Skills 与 MCP

- 从特色搭档“正则表达式生成器”新建会话并提问后，会话标题自动从搭档名改为“三字母四数字正则”；普通附件会话也能自动改名。
- Settings Skills 页面显示“可用 Skills 2”，并且实际正好列出 `network-operations` 和 `searxng-search-skill`；不再把当前设备不可发现的历史名称算入徽标。
- Android MCP 页面可进入，内置远程服务器开关和“添加服务器”入口可用；本地 `stdio` 仍按安全边界保持桌面专属。
